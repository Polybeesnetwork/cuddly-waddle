# Roadmap

See [`PRODUCT_PLAN.md`](./PRODUCT_PLAN.md) for the product thesis, validation gates, and acceptance criteria. This roadmap is evidence-first and does not authorize token issuance, payments, fundraising, or escrow.

1. **Product validation (next):** interview project operators and independent users; test whether a shareable, read-only treasury evidence page solves a recent real task. Use the explicit continue/stop criteria in the product plan.
2. **Evidence correctness:** validate successful Chain ID 56 RPC reads in supported environments; document scan coverage, cursor gaps, confirmations, reorgs, endpoint failures, token limits and retention. Add browser tests; never render demo activity as live.
3. **Evidence-room MVP (only after validation):** project-supplied address scope and provenance, confirmed transfer timeline with explorer links, separate timestamped operator context, transparent scan-health panel, and portable evidence export.
4. **Small consent-based pilots:** measure independent verification success, comprehension, repeat use and support burden. Fix false confidence and discoverability issues before expanding scope.
5. **Sustainability (only if there is repeat use):** evaluate a modest hosted workspace or sponsorship model with legal review. Preserve read-only public verification and exportability.

**Explicitly out of scope:** token issuance or gas-token claims, swaps/DeFi, payments, crowdfunding, escrow, custody, signing, and unverified safety/legitimacy scores. Any proposal to change that boundary requires separate explicit product, legal and security review; no mainnet financial operation is authorized by this roadmap.
